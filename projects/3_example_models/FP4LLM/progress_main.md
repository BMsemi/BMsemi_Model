# FP4 RRAM CIM — Main Pipeline Progress

## Pipeline Overview

```
FP4 weights/activations
        │
        ▼  Step 1: Encode
   UQ3.2 fixed point codes  {0,2,4,6,8,12,16,24}
        │
        ▼  Step 2: Compute
   5-bit ReRAM subarrays  (S⁺ and S⁻ accumulated separately in fixed point)
        │
        ▼  Step 3: Sense
   ADC  →  S⁺ or S⁻ unsigned partial sum  (bit-width = (M+N) + ⌈log₂K⌉, no sign bit)
        │
        ▼  Step 4: Subtract  ← KEY DECISION (see §3.3)
   D = S⁺ − S⁻  (exact fixed point subtraction, +1 bit for sign, before any float conversion)
        │
        ▼  Step 5: Decode
   Leading-1 detection  →  FP16  (E = p + 11,  mantissa = |D|[p-1:p-10])
        │
        ▼  Step 6: Accumulate
   Pairwise FP16 tree sum across subarrays  →  FP16/BF16 layer output
```

## 1. Quantization Variants Tested

All experiments start from the pre-trained BF16 model (`dtype=torch.bfloat16`).
Weight quantization is applied **offline** (once, before inference); activation quantization
is applied **online** (per forward pass, via pre-hooks on each `nn.Linear`).

`lm_head` is excluded because it is tied to `embed_tokens` in Qwen2.5 — in-place weight
replacement would corrupt the embedding table.
Targeted layers: `q_proj, k_proj, v_proj, o_proj` (attention) and `gate_proj, up_proj, down_proj` (MLP).

### 1.1 All Variants

| Variant | Weight quant | Activation quant | lm_head quantized? |
|---------|-------------|-----------------|-------------------|
| Baseline | none (BF16) | none (BF16) | — |
| W4A16 | FP4, per-channel | none (BF16) | no |
| WFP4AINT8 | FP4, per-channel | INT8, per-token | no |
| MXFP4_W4A4_B16 | FP4, per-block-16 (E8M0 scale) | FP4, per-block-16 (E8M0 scale) | no |
| NVFP4_W4A4_B16 | FP4, per-block-16 (E4M3 scale) | FP4, per-block-16 (E4M3 scale) | no |
| W4A4 (naive) | FP4, per-channel | FP4, per-token | no |

### 1.2 Weight Quantization (`apply_fp4_weights`)

**Per-channel scale** (`block_size=None` — used by W4A16, WFP4AINT8, W4A4):
```
For each output channel (row) j of weight matrix W:
  scale_j = max(|W[j,:]|) / 6.0          ← one scalar per output neuron
  W_q[j,:] = dequant(quantize_fp4(W[j,:] / scale_j)) × scale_j
```
Result: W_q stored back into `module.weight` as BF16. Original float weights are discarded.

**Per-block-16 scale** (`block_size=16` — used by MXFP4_W4A4_B16, NVFP4_W4A4_B16):
```
For each output channel j, group the input dimension into blocks of 16:
  For each block b (16 consecutive input elements):
    scale_{j,b} = max(|W[j, b*16:(b+1)*16]|) / 6.0   ← one scalar per 16 elements
    W_q[j, b*16:(b+1)*16] = dequant(quantize_fp4(...)) × scale_{j,b}
```
This gives 16× more scale factors than per-channel, capturing local outliers within each row.
- **MXFP4_W4A4_B16**: scale rounded to nearest power-of-2 (E8M0, OCP MX spec) — barrel shift, no multiplier
- **NVFP4_W4A4_B16**: scale stored as FP8 E4M3 — requires FP8→FP16 multiply at decode

### 1.3 Activation Quantization (runtime pre-hooks)

Hooks fire immediately before each targeted `nn.Linear` forward, replace the input tensor
in-place with the quantized-dequantized version, then the standard BF16 matmul proceeds.

**INT8 per-token** (`INT8ActivationQuantizer` — WFP4AINT8):
```
For each token t:
  scale_t = max(|x[t,:]|) / 127.0
  x_q[t,:] = round(x[t,:] / scale_t).clamp(-127, 127) × scale_t
```
One scale per token; symmetric quantization; integer range [-127, 127].

**FP4 per-token** (`FP4ActivationQuantizer` — W4A4 naive):
```
For each token t:
  scale_t = max(|x[t,:]|) / 6.0
  x_q[t,:] = dequant(quantize_fp4(x[t,:] / scale_t)) × scale_t
```
One scale per token over the full hidden dimension (e.g. 1536 elements).

**FP4 per-block-16** (`MXFP4ActivationQuantizer` / `TrueNVFP4ActivationQuantizer`):
```
For each token t, group the hidden dimension into blocks of 16:
  For each block b:
    scale_{t,b} = max(|x[t, b*16:(b+1)*16]|) / 6.0
    x_q[t, b*16:(b+1)*16] = dequant(quantize_fp4(...)) × scale_{t,b}
```
Fine-grained scale (1 per 16 elements vs 1 per 1536) is what makes block-16 FP4 viable.

### 1.4 What the RRAM Actually Stores

After offline weight quantization, the **RRAM conductance** encodes the UQ3.2 integer code
`n_w ∈ {0,2,4,6,8,12,16,24}` (one code per cell). The sign bit and per-channel/block scale
are stored in separate digital registers outside the crossbar.

For activations, the UQ3.2 code (MXFP4) or INT8 magnitude is generated by the ADC/DAC
at the crossbar periphery in real-time as each token is processed.

## 2. Operating Point Selection — What Works and Why

### 2.1 Why Naive W4A4 is Eliminated

FP4 per-token activation quantization uses a single scale per token over the full hidden
dimension (e.g. 1536 elements for Qwen2.5-1.5B). One large activation outlier forces a
large scale → all other elements round to zero or ±0.5 → **+3312 PPL (catastrophic)**.
This is confirmed empirically by RQ1 and mechanistically by RQ7 (88–95% of per-token FP4
activation codes are zero). **Block-16 scaling** (one scale per 16 elements) resolves this
by giving each outlier only local influence.

The two surviving practical operating points are:
- **WFP4AINT8** — avoids the FP4 activation problem entirely by using INT8 (127 levels),
  which is robust to outliers; compatible with Deep_gate's 8-bit ADC
- **MXFP4_W4A4_B16 / NVFP4_W4A4_B16** — fixes the FP4 activation problem via per-block-16
  scaling; achieves better PPL than W4A16 despite quantizing activations (RQ1: +2.68 vs +3.09)

### 2.2 Feasibility of Surviving Variants — RQ1 ✓

Model: Qwen/Qwen2.5-1.5B, wikitext-2 (lm_eval word-PPL), PIQA and ARC_easy 0-shot.

| Operating point    | PPL    | ΔPPL   | PIQA  | ARC_easy | Notes |
|--------------------|--------|--------|-------|----------|-------|
| BF16 baseline      | 13.310 | —      | 75.6% | 75.3%    | FP32 eval reference: 11.26 |
| NVFP4_W4A4_B16     | **15.353** | **+2.04** | 74.2% | 71.3% | FP4×FP4, per-block-16 E4M3 scale |
| MXFP4_W4A4_B16     | 15.987 | +2.68  | 74.5% | 69.4%    | FP4×FP4, per-block-16 E8M0 scale |
| W4A16              | 16.395 | +3.09  | 74.4% | 69.9%    | FP4 weights (per-channel), BF16 acts |
| WFP4AINT8          | 16.835 | +3.53  | 73.8% | 67.8%    | FP4 weights (per-channel), INT8 acts |
| W4A4 (naive)       | 3325.8 | +3312  | 55.2% | 32.1%    | FP4 acts without block scaling → catastrophic |

**Key findings:**
- Both block-16 variants **outperform W4A16**: NVFP4 +2.04, MXFP4 +2.68 vs W4A16 +3.09 —
  block-16 activation scaling more than recovers the loss from quantizing activations
- NVFP4_W4A4_B16 beats MXFP4_W4A4_B16 by 0.64 PPL, consistent with RQ11 (E4M3 vs E8M0 gap = 0.252 on token-PPL)

  supporting compatibility with a Deep_gate-style INT8 activation interface
- Naive W4A4 is catastrophic — block scaling is non-negotiable

### 2.4 Scale Format: E8M0 vs E4M3 vs FP32 — RQ11 ✓

**Question:** How much accuracy is lost by using E8M0 (barrel-shift, no multiplier) vs
E4M3 (FP8 multiply) block scales?

**Note on metrics:** RQ11 uses custom token-PPL (32×512 wikitext-2 tokens); RQ1 uses
lm_eval word-PPL. Absolute numbers differ (BF16 = 11.26 here vs 13.31 in RQ1) but
relative degradation is consistent (~20% for MXFP4 in both experiments).

| Variant          | W scale          | A scale          | PPL    | ΔPPL vs BF16 | Hardware cost |
|-----------------|------------------|------------------|--------|--------------|---------------|
| BF16            | —                | —                | 11.257 | +0.000       | baseline |
| W4A16-ch        | per-channel FP32 | BF16             | 13.965 | +2.708       | FP4 weight decode only |
| MXFP4-W4A4-B16  | E8M0 block-16    | E8M0 block-16    | 13.486 | +2.229       | shift-only (barrel shifter) |
| NVFP4-W4A4-B16  | E4M3 block-16    | E4M3 block-16    | 13.234 | +1.977       | FP8→FP16 scale multiply |
| Ideal-W4A4      | FP32 block-16    | FP32 block-16    | 13.130 | +1.873       | exact (reference only) |

| Comparison       | ΔPPL   | Interpretation |
|-----------------|--------|----------------|
| E8M0 vs ideal   | +0.356 | full cost of power-of-2 rounding |
| E4M3 vs ideal   | +0.104 | residual cost of FP8 scale quantization |
| **E8M0 vs E4M3** | **+0.252** | **hardware tradeoff: shift vs multiply** |

**Scale errors (197 weight layers):** E8M0 = 44.6% mean relative error; E4M3 = 5.8%.

**Key findings:**
1. **E8M0 shift-only path is sufficient**: 0.252 PPL gap vs E4M3, below 0.5 threshold.
   No FP8 scale multiplier needed for our RRAM-CIM design.
2. **Scale granularity dominates scale precision**: MXFP4-B16 (13.49) beats W4A16-ch
   (13.97) even with coarser E8M0 scales — per-16 granularity matters more than format.
3. **E4M3 is the upgrade path**: closes 71% of gap to ideal. If accuracy budget is tight
   and FP8 multiply is acceptable, NVFP4 is the right choice.

**Ecosystem note:** Most currently available FP4 W4A4 LLM checkpoints we inspected, including
`JongYeop/Qwen2.5-3B-Instruct-FP4-W4A4`, use **NVFP4** (E4M3 block scales, `weight_scale`
dtype = `float8_e4m3fn`). MXFP4 (E8M0) is the OCP hardware spec — shift-only hardware, no
public model zoo. Our hardware targets MXFP4_W4A4_B16; RQ11 confirms E8M0 is sufficient.

## 3. ReRAM Subarray Design

### 3.1 Weight and Activation Distributions — RQ7/RQ8 ✓

Understanding what values the RRAM cells actually store informs sensing policy, conductance
margin allocation, and programming targets.

**RQ7 — FP4 code distribution (per-tensor scale, 196 weight + 196 activation tensors):**

| Magnitude | Weight freq | Act freq (per-token) |
|-----------|------------|----------------------|
| 0.0       | 63.4%      | 94.8%                |
| 0.5       | 33.1%      | 4.6%                 |
| 1.0–6.0   | 3.5%       | 0.6%                 |

| Tensor | Layer | FP4 entropy | Zero fraction |
|--------|-------|-------------|---------------|
| Weight | attn  | 2.583 bits  | 44.6%         |
| Weight | MLP   | 2.005 bits  | 64.8%         |
| Act (per-token) | attn | 1.539 bits | 88.7% |
| Act (per-token) | MLP  | 1.262 bits | 95.1% |

**Key findings:**
1. **96.5% of weight cells at G=0 or G=0.5** — FP4 rounding, not pruning. ~63% of RRAM cells
   store G_min. G=4.0/6.0 essentially unused → those levels can have relaxed programming tolerance.
2. **Per-token activations: 88–95% zeros** — directly explains why naive per-token FP4 fails
   (§2.1): one outlier forces all others to zero. Also explains why empirical partial sums are
   11–12 bits below worst case (§3.4).
3. **Adaptive sensing gain is limited**: distribution dominated by 2 levels; reallocation only
   helps for the rare high-magnitude cells.
4. **Block-16 scaling effect**: calibrated E4M3 block-16 scales achieve entropy ≈ 4 bits
   (near-uniform) vs our per-tensor FP4 (2.0–2.6 bits) — this is the quantitative reason
   block-16 scaling recovers accuracy (RQ11).

**RQ8 — Block scale distribution:** E8M0 log₂(scale) spans a wide range with std ~0.5–0.7;
attn layers have larger scales than MLP. Power-of-2 rounding of these continuous values
produces the 44.6% mean scale error measured in RQ11.

### 3.2 Encoding: FP4 → UQ3.2 Fixed Point — RQ3 ✓

Each FP4 magnitude code is mapped to a 5-bit UQ3.2 integer `n` that can be stored directly
in a single RRAM conductance level.

**Rule:** `n = {1,m} << e` for normalised codes (e > 0), `n = m << 1` for denormal.

| FP4 mag. code | e | m | operation    | UQ3.2 code n | float value |
|---------------|---|---|--------------|--------------|-------------|
| 000           | 0 | 0 | 0            | 0            | 0.0         |
| 001           | 0 | 1 | `1 << 1`     | 2            | 0.5         |
| 010           | 1 | 0 | `10 << 1`    | 4            | 1.0         |
| 011           | 1 | 1 | `11 << 1`    | 6            | 1.5         |
| 100           | 2 | 0 | `10 << 2`    | 8            | 2.0         |
| 101           | 2 | 1 | `11 << 2`    | 12           | 3.0         |
| 110           | 3 | 0 | `10 << 3`    | 16           | 4.0         |
| 111           | 3 | 1 | `11 << 3`    | 24           | 6.0         |

`|x_FP4| = n × 2⁻²`,  `x_FP4 = sign × n / 4`

**Hardware cost:** 2-bit controlled barrel shifter + one denormal mux.
For weights: done **offline** during ReRAM programming — zero runtime overhead.

**RRAM conductance targets:** FP4 requires only 8 calibrated conductance levels out of 32
available RRAM states. The 24 unused states act as guard bands between adjacent FP4 levels,
giving wide noise margin. The targets must be calibrated proportionally to
{0, 2, 4, 6, 8, 12, 16, 24} — **not evenly spaced** (codes are sparse and non-uniform).
Hardware calibration is required; "every 4th level" is a guard-banding strategy, not the
mathematical mapping.

**Cell density vs Deep_gate INT8 differential nibble-sliced baseline (4 cells/weight):**
- FP4 with S⁺/S⁻ digital routing (sign via XOR, no sign cell stored): **1 magnitude cell/weight →
  up to 4× reduction in ReRAM magnitude-cell count** (total storage also includes sign metadata,
  block scales, and routing circuits; system-level reduction is lower)
- FP4 with separate 1-bit SLC sign cell: 2 cells/weight → **2× magnitude-cell reduction**

**GEMM equivalence (RQ3 ✓):** UQ3.2 fixed-point MAC is numerically equivalent to FP4 float MAC.

| Matrix size (N×K) | Max relative error vs FP32 |
|-------------------|---------------------------|
| 64×128            | 2.67×10⁻⁷                 |
| 256×512           | 6.59×10⁻⁷                 |
| 1024×4096         | 9.79×10⁻⁴                 |
| 4096×4096         | 7.34×10⁻⁴                 |

Error grows with matrix size but stays ≤ FP16 epsilon (~10⁻³) at 4096×4096. UQ3.2 encoding
is exact; error comes from FP16 accumulation in the reference, not from encoding itself.

### 3.3 Computing the Output

#### Step 2 — Compute: S⁺/S⁻ Unsigned Accumulators

Each subarray accumulates K rows simultaneously (or row-serially within the subarray).
Separate S⁺ and S⁻ fixed point accumulators maintained per column throughout.

```
For each row i in subarray:
  n_w = UQ3.2 weight code,   s_w = weight sign
  n_a = UQ3.2 activation code (or INT8), s_a = activation sign
  combined_sign = s_w XOR s_a
  if combined_sign == 0:  S⁺ += n_w × n_a
  else:                   S⁻ += n_w × n_a
```

**Hardware backing:**
- MEMRISYS 2025: 32-state 5-bit ReRAM; stable at 125°C; BER < 10⁻⁶ with 1-bit ECC ✓
- Deep_gate: row-serial digital CIM, S⁺/S⁻ separate accumulators confirmed ✓

#### Step 3 — Sense: ADC Bit-Width

S⁺ and S⁻ are **unsigned** accumulators — sign only enters at D = S⁺ − S⁻.
The ADC reads one unsigned accumulator at a time; **no sign bit needed at the ADC**.

- **ADC width for S⁺ or S⁻ (unsigned):** `(M+N) + ⌈log₂K⌉` bits
- **D = S⁺ − S⁻ (signed output):** `(M+N) + ⌈log₂K⌉ + 1` bits (one extra sign bit)

where M = 5 (UQ3.2 weight, max code = 24),
      N = 5 (FP4×FP4) or 7 (WFP4AINT8 — INT8 max magnitude = 127 = 2⁷ − 1; M+N=12),
      K = rows accumulated per ADC read.

**Worst-case table (FP4×FP4, M=N=5, max product = 24×24 = 576):**

| K    | max S (unsigned) | ADC bits (S⁺/S⁻) | bits for D (signed) |
|------|-----------------|-------------------|---------------------|
| 1    | 576             | 10                | 11                  |
| 4    | 2,304           | 12                | 13                  |
| 16   | 9,216           | 14                | 15                  |
| 64   | 36,864          | 16                | 17                  |
| 256  | 147,456         | 18                | 19                  |
| 1024 | 589,824         | 20                | 21                  |
| 4096 | 2,359,296       | 22                | 23                  |

**WFP4AINT8 (FP4 weight × INT8 activation, M+N=12, max product=24×127=3,048):**

| K    | max S (unsigned) | ADC bits (S⁺/S⁻) | bits for D (signed) |
|------|-----------------|-------------------|---------------------|
| 1    | 3,048           | 12                | 13                  |
| 16   | 48,768          | 16                | 17                  |
| 256  | 780,288         | 20                | 21                  |
| 1024 | 3,121,152       | 22                | 23                  |
| 4096 | 12,484,608      | 24                | 25                  |

Note: FP4×FP4 bakes 2⁻⁴ into FP16 exponent (p+11); FP4×INT8 bakes only 2⁻² (p+13),
with per-token activation scale s_a applied separately.

#### Step 4 — Subtract: D = S⁺ − S⁻ (Fixed Point Before FP16)

**Decision: subtract S⁺ − S⁻ in fixed point, before FP16 conversion.**

```
D = S⁺ − S⁻    (exact fixed point arithmetic, no rounding)
sign_out = (D < 0)
p = leading_1_position(|D|)
→ encode |D| to FP16, attach sign_out
```

**Why not subtract after FP16 conversion?**

| Option | Risk |
|--------|------|
| **A: subtract in fixed point → FP16** | ✓ no cancellation — D exact, then encode once |
| B: FP16(S⁺) − FP16(S⁻) | ✗ if S⁺ ≈ S⁻, relative error on δ = S⁺−S⁻ can be >> 0.049% |

**Example:** S⁺=10,000, S⁻=9,990, true D=10. FP16(S⁺)−FP16(S⁻) ≈ 10 ± 10 (100% error).
Fixed point: S⁺−S⁻ = 10 exactly → FP16(10) = 10 ± 0.0049 (0.049%) ✓

**Hardware:** The ADC digitizes unsigned S⁺ and S⁻ branches separately (two ADC reads per
column); D = S⁺ − S⁻ is then computed digitally at the column output before FP16 conversion.
An analog differential-sensing implementation is possible but not assumed here.
Cost: one digital adder per column output.

#### Step 5 — Decode: FP16

```
Input:  fixed point D = S⁺ − S⁻  (signed, up to 23 bits for K=4096)
Output: FP16

1. sign_bit  = (D < 0)
2. A = |D|
3. p = position of leading 1 in A  (0-indexed from LSB)
4. FP16 exponent field = p + 11
   [float value = A × 2⁻⁴ = 1.m × 2^(p−4);  FP16 exp = (p−4) + 15 = p + 11]
5. FP16 mantissa = A[p−1 : p−10]  (10 bits below leading 1)
6. Assemble FP16: [sign_bit | exp(5b) | mantissa(10b)]
```

**Precision:** Relative error = 2⁻¹¹ ≈ 0.049% (half-ulp, round-to-nearest-even), constant
regardless of K. Requires guard/round/sticky bits; truncation gives 2⁻¹⁰ ≈ 0.098%.

| K    | bits in D (wc) | FP16 mantissa bits | bits lost | rel. error |
|------|---------------|--------------------|-----------|------------|
| 1    | 11            | 11                 | 0         | 0.049% (lossless) |
| 16   | 15            | 11                 | 4         | 0.049%     |
| 64   | 17            | 11                 | 6         | 0.049%     |
| 1024 | 21            | 11                 | 10        | 0.049%     |
| 4096 | 23            | 11                 | 12        | 0.049%     |

#### Step 6 — Accumulate: FP16 Tree → BF16 Output

```
Subarray 0: FP16(D₀)  ─┐
Subarray 1: FP16(D₁)  ─┤─ FP16 add ─┐
Subarray 2: FP16(D₂)  ─┤             ├─ FP16 add ─ ... → FP16/BF16-compatible layer output
Subarray 3: FP16(D₃)  ─┘─ FP16 add ─┘                    (stored as BF16 before residual/norm)
```

Pairwise (binary tree) summation: error ≈ log₂(P) × 0.049%.

For **per-channel-scaled W4A16/WFP4AINT8**, the scale product `s_w × s_a` can be applied once
after the full tree reduction (one FP16 multiply per output element).
For **block-scaled MXFP4/NVFP4**, each block-aligned partial sum D_b must be multiplied by its
corresponding `s_{w,b} × s_{a,b}` before accumulation across blocks:

  y = Σ_b  (s_{w,b} × s_{a,b} / 16) × D_b

MXFP4/E8M0 applies this via exponent shift; NVFP4/E4M3 requires an FP8→FP16 scale multiply.
The final output can be cast to BF16 for compatibility with residual/norm stages; this cast may
round mantissa bits but preserves the BF16 model interface.
**Hardware cost:** fixed-width FP16 adder tree — does NOT grow with P.

### 3.4 Subarray Size K — Precision vs Area Tradeoff ✓

**Block-alignment constraint (MXFP4_W4A4_B16):** K must be a **multiple of 16** (hardware rule).
Integer products from different scale blocks cannot be accumulated into one unscaled integer sum
unless their scale products are identical; subarray boundaries must therefore align to the
16-element scale block, or the hardware must maintain per-block partial sums internally.
WFP4AINT8 has no block constraint.

#### Fixed-point accumulator knee — RQ9 ✓

Per-tensor fixed-point quantization applied to every linear layer output (worst-case simulation):

| N bits | MXFP4_W4A4_B16 PPL | ΔPPL   | WFP4AINT8 PPL | ΔPPL   |
|--------|----------------|--------|---------------|--------|
| 8      | 34.14          | +20.7  | 38.07         | +23.7  |
| 10     | 24.52          | +11.0  | 25.13         | +10.8  |
| 12     | 17.45          | +4.0   | 16.96         | +2.6   |
| **14** | **13.80**      | **+0.3** | **14.50** | **+0.1** |
| 16     | 13.59          | +0.1   | 14.32         | −0.05  |
| inf (baseline) | 13.49 | — | 14.37 | — |

**Knee at N=14** for both operating points.

**⚠ Critical interpretation — per-tensor fixed-point ≠ FP16 per-element decode:**
RQ9 simulates per-tensor fixed-point (one scale per entire layer output tensor). Layer outputs
have 23–34 bit dynamic range; a per-tensor N=11 quantizer zeros out all small-but-valid values.
FP16 sub-sum decode is **per-element**: each D gets its own exponent, so small and large D are
both encoded with ~0.049% error. The N=14 knee is a pessimistic bound for fixed-point
hardware — FP16 per-element decode is expected to match baseline accuracy (confirmed RQ9c ✓).

### 3.5 RRAM Noise Tolerance — RQ4 ✓

**Operating point:** W4A16 (per-channel FP4 weights), baseline PPL = 13.965

**Why W4A16:** RRAM stores only weights; activations are generated by ADC periphery at
inference time and are not subject to RRAM cell noise. W4A16 isolates weight noise cleanly.
WFP4AINT8 uses the same per-channel FP4 weight format, so these thresholds transfer directly.
MXFP4_W4A4_B16 (per-block-16 weights) may differ slightly and could warrant a separate sweep.

p_stuck are co-applied. They are separate sweeps shown side-by-side for compactness.

**Tolerance thresholds (ΔPPL < 0.5):**
- **σ_rel ≤ 0.05** (5% conductance noise): safe — typical RRAM σ_rel = 1–3%, well within budget
- **p_stuck < 0.01%** (1 in 10,000 cells): MEMRISYS-2025 post-ECC BER < 10⁻⁶ = 0.0001% ✓
- **p_sign_flip ≈ 0.05–0.1%**: sign flip is most sensitive; sign ECC recommended

**Key insight:** FP4 uses only 8 of 32 RRAM states → wide guard bands → high noise margin.
FP4 quantization noise (+2.68 PPL) dominates over hardware noise at safe operating points —
RRAM noise is **not the accuracy bottleneck**.

### 3.6 Photonic Integration — RQ5/RQ6 ✓

**RQ5 — Full layer output ENOB (196 linear layers, FP4 weights + BF16 activations):**

| Layer type | ENOB mean | Required bits mean | DR mean  |
|------------|-----------|-------------------|----------|
| attn       | 28.0      | 29.5              | 1.07×10⁹ |
| mlp        | 28.2      | 29.8              | 1.33×10⁹ |

**RQ6 — Sensitivity to accumulator bits (ΔPPL vs baseline 13.97):**

| Scope      | N=8    | N=10   | N=12  | N=16  |
|------------|--------|--------|-------|-------|
| all layers | +22.7  | +10.4  | +2.7  | ≈0    |
| attn only  | +0.85  | ≈0     | ≈0    | ≈0    |
| mlp only   | +17.1  | +10.4  | +2.7  | ≈0    |

**Key findings:**
1. **Full-column analog accumulation needs ~28–30 ENOB** — beyond practical photonics.
2. **MLP is the bottleneck**: MLP-only requires N≥16; attn-only safe at N=8.
3. **Row-serial + digital accumulation eliminates the problem**: ADC sees only a single-row
   partial product — **10-bit worst-case for FP4×FP4** (max 24×24=576) or **12-bit for
   FP4×INT8** (max 24×127=3048) — before digital accumulation. The ~28 ENOB requirement
   disappears. (The "9-bit ADC" from Deep_gate applies to their INT4 design where max
   product = 24×15=360 < 512 = 2⁹.)
4. **Recommendation**: use row-serial decomposition (like Deep_gate). If partial analog
   accumulation is needed, restrict it to attention layers where N=8 suffices.

## 4. Research Claim (Draft)

> We map E2M1 FP4 magnitudes exactly into sparse 5-bit UQ3.2 codes {0,2,4,6,8,12,16,24},
> enabling the ReRAM array to perform fixed-point magnitude MACs while FP4 decoding is handled
> by lightweight shift/mux logic. Signed products are accumulated as separate unsigned S⁺ and S⁻
> partial sums; the signed local difference D = S⁺ − S⁻ is computed in fixed point before
> floating-point conversion to avoid catastrophic cancellation. Each signed subarray result is
> decoded to FP16 by leading-one detection, with exponent p+11 for FP4×FP4 (product scale 2⁻⁴)
> and p+13 for FP4×INT8 (weight scale 2⁻², per-token activation scale applied separately).
> Assuming round-to-nearest-even (guard/round/sticky bits), local relative rounding error is
> bounded to 2⁻¹¹ ≈ 0.049% per element; truncation gives 2⁻¹⁰. Global accumulation uses
> pairwise FP16 tree reduction, bounding total error to O(log₂P × 2⁻¹¹).
> Block-scaled FP4 activations are required for robustness; E8M0/MXFP4 block scales provide a
> shift-only hardware path with only a 0.252 PPL penalty relative to true E4M3/NVFP4 scales.
>
> **Caveat on subarray size:** FP16 decode is analytically safe only up to K≤1819 (FP4×FP4)
> and K≤85 (FP4×INT8) under worst-case assumptions. For larger K, empirical partial-sum
> monitoring on the measured Qwen2.5-1.5B workload confirms safety (max observed sub-sum ≈49.7
> at K=4096, well below FP16 max 65504) due to ~88–95% activation sparsity; worst-case-guaranteed
> operation at K>1819 requires BF16/FP32 decode or saturation logic.
