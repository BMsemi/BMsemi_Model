# Photonic Interconnect Bandwidth Analysis for LLM Inference

Quantifies the data volume (bits) that a photonic interconnect must carry
in two scenarios and across common LLM data formats.

## 2. Data Formats

| Format | Bits/element | Description | Bandwidth group |
|--------|-------------|-------------|----------------|
| FP16 | 16 | float16 (5e+10m) | 16-bit |
| FP16-FXP | 16 | INT16, scale=FP16_MAX/32767 | 16-bit |
| BF16 | 16 | bfloat16 (8e+7m) | 16-bit |
| BF16-FXP | 16 | INT16, scale=BF16_MAX/32767 | 16-bit |
| INT8 | 8 | INT8 + per-tensor scale | 8-bit |
| FP8-E4M3 | 8 | float8 E4M3 (4e+3m) | 8-bit |
| INT4 | 4 | INT4 + per-tensor scale | 4-bit |

**Note:** FP16 and FP16-FXP are both 16 bits/element — identical bandwidth.
Fixed-point variants simplify photonic interface hardware (no per-element exponent)
but do not reduce link bandwidth.
INT8/FP8 halve the bandwidth; INT4 quarters it.

---

## 3. Scenarios

| Scenario | Description | Transfers per forward pass |
|----------|-------------|---------------------------|
| attn_to_mlp | Hidden state [L, d] from attention output to MLP input (same layer) | num_layers |
| layer_to_layer | Hidden state [L, d] from layer n output to layer n+1 input | num_layers − 1 |

For decode (autoregressive): L = 1 regardless of KV-cache length.

## 5. Where Photonic Interconnects Can Be Used in LLM Inference

### 5.1 Layer pipelining (chip-to-chip, layer_to_layer scenario)
Distribute transformer layers across multiple accelerator chips.
Each chip processes K consecutive layers, then sends the hidden state
over a photonic link to the next chip.
- **Bandwidth requirement**: one hidden-state transfer per layer boundary.
- **Prefill bottleneck**: scales with L; at L=65536, Llama-70B requires
  ~8 Gb per hop in FP16 (see table above).
- **Decode is trivial**: L=1, so only d × bpe bits per hop.

### 5.2 Attention–MLP disaggregation (attn_to_mlp scenario)
Separate attention and MLP onto different compute tiles or chiplets.
Photonic link carries the hidden state from attention output to MLP input
and back. Bandwidth identical to layer_to_layer per hop, but fires num_layers
times (both forward directions) per pass.
- Attractive if attention and MLP have different optimal hardware
  (e.g., RRAM-CIM for MLP weights, SRAM for attention KV cache).

### 5.3 KV cache offload
Long-context inference requires storing K and V tensors for all past tokens.
KV tensor size per layer = 2 × num_kv_heads × head_dim × L × bpe.
Photonic link to off-chip optical memory avoids DRAM bandwidth bottleneck.
- At L=65536, Llama-3.1-8B (GQA, 8 KV heads, head_dim=128):
  2 × 8 × 128 × 65536 × 2 bytes = 268 MB per layer, × 32 layers = 8.6 GB total KV.
- This dwarfs the hidden-state transfer; photonic memory bandwidth is the
  primary constraint for long-context decode.

### 5.4 Tensor parallelism all-reduce
Multi-GPU tensor parallelism splits each weight matrix column-wise.
After each matmul, an all-reduce across TP ranks recombines partial sums.
All-reduce volume = hidden_dim × L × bpe per layer.
Photonic links between GPUs (replacing NVLink / InfiniBand) can provide
higher bandwidth and lower latency for the all-reduce.

### 5.5 MoE expert routing
In MoE models (DeepSeek-V3, Mixtral), tokens are routed to top-K experts
which may reside on different chips.
Routing traffic = top_K × hidden_dim × n_tokens × bpe per MoE layer.
Photonic all-to-all enables expert parallelism without electrical mesh bottlenecks.

### 5.6 Summary: which scenario benefits most from photonics

| Use case | Prefill bandwidth | Decode bandwidth | Key driver |
|----------|------------------|-----------------|------------|
| Layer pipelining | High (scales with L) | Low (fixed d) | Prefill throughput |
| Attn–MLP split | Same as above | Low | Hardware heterogeneity |
| KV cache offload | High (write all KV) | Very high (read KV per step) | Long-context decode |
| TP all-reduce | High | Low | Model parallelism |
| MoE routing | Moderate | Moderate | Expert parallelism |

**Photonics is most advantageous where:**
1. Large tensors must cross a physical boundary (chip-to-chip, tile-to-tile)
   at high bandwidth and low latency.
2. The link fires frequently (every layer) — photonic link latency dominates
   when the payload is small (decode), so minimising per-packet overhead matters.
3. INT8 or INT4 quantization of the transferred tensor directly halves/quarters
   the required photonic bandwidth, making quantisation a first-class design knob.

---

## 6. Key Observations

- At L=65536, Llama-3.1-70B in FP16: 8.59 Gb per single hop. INT8 halves this to 4.29 Gb.
- At L=65536, Qwen2.5-1.5B (our target model) in FP16: 1.61 Gb per single hop.
- Decode (L=1), Llama-3.1-70B in FP16: 131.07 kb per hop — link latency dominates over bandwidth in this regime.
- FP16 and BF16 have identical bandwidth (both 16 bits/element).
- Fixed-point variants (FP16-FXP, BF16-FXP) also use 16 bits — no bandwidth saving,
  but simpler photonic modulator hardware (binary integer, no exponent field).
- INT8/FP8 halve the photonic bandwidth requirement with modest accuracy cost
  (WFP4AINT8 shows INT8 activations are accuracy-competitive, §2.2).
